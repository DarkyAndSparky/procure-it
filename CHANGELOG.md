# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/).
Версии — по внутренней схеме `YYwWWr-bNN` (год-неделя, релиз/билд).

Этот файл — единственный источник истины для истории изменений: раздел
«Последние изменения» на странице «О системе» приложения парсит именно его
(`src/changelog.js`), отдельного дублирующего списка в коде нет.

**Каждый значимый коммит должен добавлять сюда запись.** Pre-commit хук
(`scripts/hooks/pre-commit`, ставится через `npm install` → `prepare`)
напоминает об этом, если меняются файлы в `src/`, `public/js/` или
`public/*.html`, а `CHANGELOG.md` в этом же коммите не тронут.

## [26w34-b03] — 2026-08-20

### Добавлено
- `scripts/check-node-version.js` и `scripts/check-deps-fresh.js` — проверка версии Node.js и актуальности зависимостей вынесены из inline `node -e`/batch-логики в отдельные `.js`-файлы, общие для `.sh` и `.bat`

### Изменено
- **`install.bat`/`start.bat`/`test.bat` переписаны по проверенно-рабочему паттерну** (образец — рабочий проект пользователя): кириллица в `echo` вернулась (в b02 была убрана до ASCII), но теперь без факторов, из-за которых ломалось в b01 —
  · разделители — простой ASCII `===`, не символы псевдографики (`══`, 3-байтовые UTF-8);
  · вся версия-чувствительная логика — через `node scripts\check-node-version.js`/`check-deps-fresh.js` (простой вызов без спецсимволов на строке `.bat`), а не `node -e "..."` с кучей скобок/кавычек вперемешку с русским текстом на одной строке;
  · убраны `if/else`-конструкции — только последовательные одиночные `if X (...)`, как в образце;
  · убран вызов одного `.bat` из другого с передачей флага (`call install.bat --from-start`) — `start.bat`/`test.bat` теперь самодостаточны, с небольшим дублированием проверки вместо кросс-файловой связи;
  · литеральные скобки внутри кириллического текста экранированы (`^(...^)`).
  `install.sh` тоже переведён на общие `scripts/check-node-version.js`/`check-deps-fresh.js` — та же логика проверки версии/актуальности зависимостей на обеих платформах, не может разойтись.

## [26w34-b02] — 2026-08-20

### Исправлено
- **`.bat`-скрипты не запускались на реальной Windows** — в b01 весь
  видимый текст в `install.bat`/`start.bat`/`test.bat` был переведён на
  русский в расчёте на `chcp 65001`. На практике не сработало: `cmd.exe`
  не гарантированно читает сам batch-файл как UTF-8 при токенизации
  команд — ломались не только `echo`, но и `rem`-комментарии, скрипты
  падали с ошибками вида `'—' is not recognized as an internal or
  external command`. Все три `.bat`-файла переписаны в чистый ASCII
  (включая комментарии, не только видимый текст). `.sh`-версии кириллицу
  сохранили — той же проблемы там нет: bash токенизирует байтовые потоки
  равномерно, шелл-метасимволы все в ASCII, конфликтовать с
  многобайтовыми UTF-8-последовательностями кириллицы им негде

## [26w34-b01] — 2026-08-20

### Добавлено
- Модалка подтверждения восстановления из бэкапа с реальными цифрами «сейчас / будет» вместо голого `confirm()`
- Защита от дублирования организаций — по короткому названию и по фактической папке раскладки файлов (регистронезависимо, включая кириллицу), проверяется и при создании, и при редактировании
- Фильтр по «Контрагенту» в реестре заявок
- Формат документа «Сопровождение» — Акт гарантийного обслуживания (гарантийный срок, без блока «Порядок оплаты», условия гарантии)
- Ленивая генерация детальной строки реестра — только при первом разворачивании конкретной заявки, а не заранее для всех строк страницы
- Импорт организаций списком — модалка на странице «Организации», построчный парсинг (`;` или Tab), построчный отчёт о добавленных/пропущенных
- `install.sh`/`install.bat` — установка зависимостей без запуска сервера (выделены из `start.*`, которые теперь их вызывают, а не дублируют логику)
- `test.sh`/`test.bat` — отдельный запускатор тестов, не завязан на `start`/`install`

### Изменено
- `playwright` перенесён из `dependencies` в `devDependencies` — нигде не используется в коде/тестах, реально пропускается `npm ci --omit=dev` (в т.ч. в Dockerfile), заметно снижая вес прод-инсталла

### Исправлено
- `start.bat` открывал браузер по фиксированному таймеру параллельно со стартом сервера (гонка, могла открыть браузер раньше готовности сервера) — перенесено в колбэк `.listen()` в `server.js`, управляется `PROCURE_AUTO_OPEN=1`
- `start.bat` требовал двух запусков после свежей установки — `npm install` вызывался без `call`, что в Windows batch обрывало выполнение родительского скрипта сразу после установки зависимостей. Исправлено (`call npm install` в `install.bat`), заодно добавлены `cd /d "%~dp0"` и CRLF-окончания строк во всех `.bat`-файлах для устойчивости
- `install.sh`/`install.bat` не проверяли минимальную версию Node.js и не отличали сбой `npm install` (нет интернета, заблокирован registry) от успеха — оба добавлены, с понятными сообщениями об ошибке
- Проверка «нужно ли переустанавливать зависимости» была завязана на существование одного пакета (`node_modules/express`) — теперь сравнивается время изменения `package-lock.json` против `node_modules` (в `.bat` — через `node -e`, не через batch-даты, которые зависят от региональных настроек Windows)
- `test.sh`/`test.bat` дублировали часть проверок install-скриптов — переписаны на вызов `install.*` с флагом `--from-start`
- Все `.bat`-скрипты (`install.bat`/`start.bat`/`test.bat`) переведены на русский — были на английском, тогда как `.sh`-версии на русском; несогласованность для пользователей с русской локалью Windows
- Утечка секретов вебхуков (Bitrix24, статус) в скачиваемый JSON-бэкап — исключены из выгрузки так же, как пароль сетевой папки
- Command injection через название заявки при открытии папки заявки и через логин/пароль сетевой папки на Windows — переведено на `execFile`/массив аргументов без участия shell
- Общая PBKDF2-соль на всех пользователей заменена на соль-на-пользователя, с автоматической миграцией существующих записей при следующем входе
- Восстановление из бэкапа не проверяло роль пользователя по белому списку `['viewer','operator','admin']`, в отличие от обычного создания/редактирования пользователя
- `GET /api/system-info`(`/outdated`) сужен до `adminOnly` — приведён в соответствие с видимостью страницы «О системе» в UI (уже была только для admin)
- `Date.now()` как id организаций/заявок заменён на `crypto.randomUUID()` — исключена теоретическая гонка при параллельном создании
- `GET /api/backup` (JSON) добавлен под тот же `strictLimiter`, что и `GET /api/backup/db`
- `requireSafeId` добавлен на GET `/requests/:id/signed-spec` и `/invoice-file` — defense-in-depth наравне с POST-роутами
- Сервер логирует расхождение между суммой заявки/закупки, присланной клиентом, и пересчитанной из `positions` той же формулой (`pricing-core.js`) — не блокирует сохранение, только предупреждение в лог
- Автотесты на аутентификацию (`test/auth.test.js`) — соль-на-пользователя, миграция легаси-форматов пароля (общая PBKDF2-соль и самый старый голый SHA-256) при успешном входе, отказ на неверном пароле без побочной миграции
- Сравнение секретов через обычное `===` заменено на timing-safe (`crypto.timingSafeEqual`) — конкретно `password === LEGACY_PASSWORD` в `findUserByCredentials` (сравнение сырого секрета, а не хэша — реальный, не теоретический риск тайминг-атаки), заодно и сравнения хэшей паролей для единообразия; покрыто автотестами (`timingSafeStringEqual` — совпадение/несовпадение/разная длина/пустые значения)
- `Dockerfile` — сборка образа падала на первом же `RUN npm ci`: `package.json` копировался раньше `scripts/`, а `prepare`-хук (`node scripts/install-hooks.js`) запускается именно при `npm ci`. Не всплывало раньше, потому что Docker CI (`docker.yml`) триггерится только на push git-тега, а ни одного тега с момента появления `prepare`-хука ещё не было — нашлось и исправлено перед первым релизным тегом
