## 🔴 Приоритет — надёжность и данные

- [ ] **Автотесты хотя бы на расчёты и генерацию документов** — сейчас CI
      (`ci.yml`) проверяет только синтаксис (`node --check`), логику — никак.
      За последний цикл несколько багов всплывали именно в формулах наценки/
      доставки и генерации `.docx` (округление, отступы, опечатка в именах
      свойств границ таблицы, дублирование номеров спецификаций) — простой
      набор unit-тестов на `docxService.js` и на формулу цены с наценкой
      поймал бы их ещё до ручной проверки на печати.
- [ ] **Подтверждение перед восстановлением из JSON** — проверить, что
      `restoreBackup()` явно предупреждает «сейчас будут перезаписаны текущие
      данные» с количеством затрагиваемых записей, а не просто тихо
      применяет файл по первому клику.
- [ ] **Защита от дублирования организаций** — ничего не мешает завести две
      организации с одинаковым коротким названием, что путает и нумерацию
      спецификаций, и раскладку файлов по папкам (обе разложатся в одну и ту
      же папку `orgFolder`).

## 🟡 Следующий приоритет

- [ ] **Фильтр по «Контрагенту» в реестре** — поле `counterparty` уже
      добавлено, сохраняется и попадает в детальную карточку заявки, но
      фильтра по нему в реестре ещё нет (только организация/месяц/статус/
      поставщик) — а вводили его именно ради будущих фильтров по магазинам.
- [ ] **Ленивый рендер деталей строк реестра** — сейчас при загрузке
      страницы генерируется полная развёрнутая HTML-разметка для КАЖДОЙ
      заявки сразу, даже свёрнутой. На текущих объёмах незаметно, но с
      ростом до многих сотен/тысяч заявок это будет ощутимо тормозить
      первый рендер страницы. Генерировать содержимое строки при первом
      разворачивании, а не заранее для всех.
- [ ] **Определиться с форматом «Сопровождение»** — тип документа существует
      в списке с 26w31, но генерация для него до сих пор заглушка
      (`'Порядок оплаты будет определён после согласования формата
      документа.'`).

## 🔵 Планируется

- [ ] **Импорт организаций списком** — сейчас справочник организаций
      заполняется только вручную по одной; при первом разворачивании на
      новую компанию/подрядчика было бы удобно закинуть сразу список.
- [ ] **CSV-экспорт реестра** — в дополнение к существующему Excel-экспорту,
      для внешних систем/BI, которым проще парсить CSV.
- [ ] **Автокомплит в выборе организации** — обычный `<select>` в форме
      заявки станет неудобным при заметном росте числа организаций
      (сейчас единицы, но тенденция понятна).

## 💡 Идеи / backlog

- [ ] **Проверка устаревших пакетов на странице «О системе»** — список
      зависимостей там уже динамический (версии резолвятся из
      `node_modules`), логичное продолжение — сравнение с последней версией
      на npm и пометка устаревших.
- [ ] **История изменений по позициям, а не только по заявке целиком** —
      сейчас audit log показывает CREATE/UPDATE/STATUS/DELETE на уровне
      заявки; более гранулярный diff по конкретным позициям был бы полезен
      при частых правках количества/цены.
- [ ] **Уведомления об изменении статуса** (email/Telegram/webhook отдельно
      от Bitrix) — сейчас статус меняется молча, историю видно только зайдя
      в заявку.

## ✅ Выполнено (26w29 → 26w31, этот цикл работы)

- Тип документа влияет на префикс номера спецификации (П/Р/М/С) и на состав
  самого документа (реализация — без ссылки на договор и порядка оплаты,
  одна сторона в подписи)
- Уникальность номера спецификации переведена с глобальной на область
  «организация + номер» — устранены ложные конфликты между разными
  организациями
- Поле «Контрагент» (магазин/поставщик закупки) в заявке
- Умный импорт позиций из Excel — автоопределение колонок по заголовкам
  вместо жёсткого позиционного формата, автовыбор закупочной (не продажной)
  цены, подтяжка суммы доставки из шапки файла
- Округление до 2 знаков во всех расчётах и Excel-формулах (`ROUND(...,2)`)
- Единый паттерн имён скачиваемых файлов (`{краткое}_Тип_{номер}`) везде —
  спецификация, расчёты, подписанный PDF
- Красная строка в `.docx` через явную табуляцию вместо `w:ind firstLine`
  (надёжнее при печати в реальном Word)
- Исправлена опечатка в границах служебных таблиц (`insideH`/`insideV` →
  `insideHorizontal`/`insideVertical`)
- Ширина таблицы спецификации приведена в точное соответствие полям страницы
- Настраиваемая папка для автобэкапов (по умолчанию — как раньше) — бэкап
  больше не обязан лежать на том же диске, что и рабочие данные
- Бэкап и восстановление физических файлов (подписанные спецификации, счета)
  через зеркало, синхронизируется при каждом автобэкапе
- Статус раскладки файлов в сетевую папку — проверяется по требованию
  (открытие строки реестра + опрос раз в 5 минут для раскрытых строк),
  переживает перезапуск сервера
- Страница «О системе» — версия, лицензия (со скачиванием текста),
  окружение (живое, обновляется раз в 10 сек), технологии, счётчики данных,
  полный список зависимостей с реально установленными версиями
- Исправлен постоянный сброс версии в сайдбаре после логина/смены пароля
- Кэш статики (`Cache-Control`) переведён с часового `max-age` на
  `no-cache` — обновления кода подхватываются сразу, без ручной очистки
  кэша браузера
- «Конфиг» переименован в «Настройки», реорганизация страницы (Bitrix24
  внизу, кнопки сохранения прилипают к низу экрана, «О системе» вынесено в
  сайдбар компактным блоком)
- Поле «Префикс» убрано из организаций (номер спецификации больше не
  завязан на него)
