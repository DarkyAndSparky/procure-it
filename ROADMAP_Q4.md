## 1. Принципы квартала

В текущем масштабе проекта (2 человека, максимум 4–5 пользователей) приоритеты следующие:

1. Надёжность и сохранность данных.
2. Удобство ежедневной работы.
3. Прозрачность процесса закупки.
4. Понятность для руководителя.
5. Минимум архитектурного усложнения.

### В этом квартале не делаем

- PostgreSQL;
- микросервисы;
- Kubernetes;
- Redux;
- Next.js;
- полный rewrite frontend;
- сложный RBAC;
- отдельную инфраструктуру ради инфраструктуры.

**React + TypeScript** рассматриваются только как небольшой прототип в конце квартала, если это действительно оправдано.

фильтров (организация/месяц/поставщик/контрагент) — `<select>` с
`<option>`, которые перестраиваются динамически из уже загруженных

которыми уже помечался выбранный `<option>` при перестройке (этот
механизм уже существовал — для сохранения выбора между перерендерами,
не для восстановления из URL, но подошёл без изменений).

## Неделя 11

### Проверить

- [x] Кириллицу. — round-trip через реальный `.xlsx`: кириллица и эмодзи
      (статусы вида «📦 Заказано») сохраняются и читаются без искажений
- [x] Даты. — хранятся текстом в ISO-формате (`2026-09-20'), не нативной
      Excel-датой. Читаемо и сортируется корректно как текст — **не
      баг**, но и не идеал (не даёт Excel-арифметику по датам); отмечено
      как возможное отдельное улучшение, не стал трогать в рамках
      «проверить»
- [x] Денежные значения. — **был баг**: без числового формата на ячейке
      Excel мог показывать сумму как есть в «Общем» формате, что для
      обычных чисел нормально, но для очень крупных сумм неприятно
      выглядит и режет копейки визуально. Добавлен формат `#,##0.00 "₽"`
- [x] Большие числа. — **был реальный баг**: суммы от ~1 млн (обычный
      сценарий для закупки серверов/сетевого оборудования) отображались
      в Excel округлёнными до целого — `999 999 999.99` превращалось в
      `1000000000` на экране (сами данные в ячейке не портились, только
      то, что видит открывший файл человек — а это и есть весь смысл
      экспорта). Тот же формат `#,##0.00 "₽"` чинит это заодно
- [x] Длинные названия. — не обрезаются, колонка просто шире/с переносом в Excel
- [x] Пустые значения. — корректно `''`, не `"null"`/`"undefined"`
- [x] Фильтрацию перед экспортом. — уже была верно реализована

### Улучшить

- [x] Экспорт текущего фильтра. — уже работал (`allReqs` — полный
      отфильтрованный, не постраничный набор), при первом чтении кода

      Сумма (₽), Статус, Путь папки)

### Важный технический урок (зафиксирован в комментариях кода)

Символ ₽ в строке числового формата Excel **обязан** быть в кавычках как
литерал (`"#,##0.00 \"₽\""`) — без них это невалидный формат:
`XLSX.SSF.format()` кидает `Error: unrecognized character ₽`. Реальный
пакет `xlsx` при ЗАПИСИ файла эту ошибку не показывает (записывает как
есть), только при попытке её отрендерить/распарсить — то есть баг было
бы видно только при открытии в настоящем Excel, не при простом
прогоне кода. Нашёл только потому, что проверял реальной генерацией +
чтением файла обратно + вызовом `SSF.format()`, а не чтением JS-кода.

# 18. Главное правило квартала

> **Не переписывать то, что уже работает, пока проблема не доказана.**

Текущая архитектура подходит вашему масштабу.

Ценность следующего квартала должна появляться от:

**надёжности → прозрачности → удобства → аналитики**

а не от количества новых технологий.

## Финальная цель

В конце квартала Procure-IT должен восприниматься не как:

> «Мой внутренний проект, который я постоянно допиливаю»

а как:

> **«Рабочая система ИТ-отдела, у которой есть резервное копирование, восстановление, понятный workflow, история операций, отчётность и документация».**

Это хорошая и реалистичная цель на один квартал.
