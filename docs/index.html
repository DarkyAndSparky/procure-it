procure-it

Self-hosted web tool for IT asset procurement — manage purchase requests, calculate prices, generate Excel sheets and specifications.

26w35-r01 MIT Node.js 18+ SQLite HTTPS
GitHub Repository 🐛 Issues

Быстрый старт

Единственное требование — Node.js 18+. Скачать: nodejs.org (LTS версия).

Windows

Дважды кликнуть start.bat

При первом запуске автоматически устанавливаются зависимости (~1 мин) и генерируется TLS-сертификат.

Linux / macOS

chmod +x start.sh && ./start.sh

Аутентификация

В приложении встроена система пользователей с тремя ролями:

РольДоступ
viewerТолько чтение — без входа вообще
operatorСоздание/редактирование заявок, организаций, загрузка файлов
adminВсё, что может operator, плюс пользователи, настройки, восстановление из бэкапа

При первом запуске автоматически создаётся администратор — логин admin, случайный пароль (выводится в консоль при старте) — и приложение сразу требует сменить пароль. Управление остальными пользователями — в пункте «Учётные записи» бокового меню (только для admin).

PROCURE_PASSWORD — это legacy-заглушка, а не основной механизм входа: она работает только пока в базе вообще нет ни одного пользователя (например, самый первый запуск до первого входа через интерфейс). Как только появился хотя бы один пользователь, PROCURE_PASSWORD игнорируется — доступом управляют через интерфейс.

Заявки

Основная единица работы. Каждая заявка содержит:

  • Организация — выбирается из справочника с автокомплитом (поиск по короткому и полному названию), автоматически подставляет договор и адрес доставки
  • Тип документа — влияет и на префикс номера спецификации, и на содержимое самого документа (см. таблицу ниже)
  • Номер задачи Битрикс — для связи с системой задач
  • Контрагент — магазин/поставщик, у которого закупали (можно фильтровать заявки по нему в реестре)
  • Номер счёта поставщика — текстовое поле, только для справки, отдельно от прикреплённого файла счёта
  • Гарантийный срок — только для типа «Сопровождение», по умолчанию 12 месяцев
  • МОЛ — материально ответственное лицо / получатель
  • Позиции — таблица товаров с полями: наименование, комментарий/ФИО, ссылка, кол-во, ед., цена закупа

Тип документа и номер спецификации

Номер спецификации формируется как {префикс}{ГГГГММ}-{№ в месяце}, где префикс зависит от выбранного типа документа:

Тип документаПрефиксОсобенности документа
📦 Товары (спецификация)ПОбычная спецификация: договор в шапке, порядок оплаты, Поставщик/Покупатель
🔧 Услуги монтажаМ«Спецификация на выполнение работ», акт вместо накладной
🏪 РеализацияРТовар для себя: без наценки (включается автоматически), без блока «Приложение №1 к договору», без «Порядка оплаты», одна сторона в подписи вместо Поставщик/Покупатель
🛠️ СопровождениеС«Акт гарантийного обслуживания»: гарантийный срок (по умолчанию 12 месяцев), условия покрытия, без «Порядка оплаты» — обслуживание в рамках срока бесплатно
Номер уникален в рамках организации, а не глобально — у разных организаций может быть одинаковый номер (П202608-01 у обеих), это нормально. Повторно тот же номер у одной и той же организации использовать нельзя.

Расчёт цены продажи

Формула соответствует оригинальному Excel-шаблону:

% от заказа  = цена_закупа_строки / итого_закупа
доля_доставки = % от заказа × стоимость_доставки
цена_с_дост   = цена_закупа + доля_доставки / кол-во
цена_продажи  = цена_с_дост × (1 + наценка%)

Все денежные значения (закуп, доставка, продажа — в рублях) округляются до 2 знаков после запятой как в интерфейсе, так и в формулах Excel-экспорта, чтобы не было длинных хвостов вроде 56639,8048645469.

Формула верифицирована по трём реальным файлам (ЯП июнь, ЛД июнь, ИП Рогулькин июль) — все 16 позиций совпали с точностью до копейки.

Шаблоны позиций

Часто используемые наборы товаров можно сохранить как шаблон (кнопка «💾 Шаблон») и добавлять одним кликом из выпадашки «+ Из шаблона».

Перетаскивание позиций

Строки таблицы позиций можно перетаскивать за иконку ⠿ слева для изменения порядка. Нумерация и расчёты обновляются автоматически.

Импорт из Excel

Загрузи прайс-лист поставщика или собственный экспорт «Расчётов» этого же приложения — импорт сам находит строку заголовков на любом листе книги (ищет колонку «Наименование») и по названиям колонок определяет, где Кол-во / Ед. / Цена / ФИО / Ссылка, независимо от их порядка. Если заголовков нет вообще — используется простой позиционный формат:

Наименование | Кол-во | Ед. | Цена

Если в книге несколько листов с ценами (например «Расчёты» + «Спецификация»), автоматически выбирается лист с закупочной ценой, а не ценой продажи — иначе при повторном импорте наценка задвоилась бы. Цена округляется до 2 знаков. Если в шапке файла есть общая сумма доставки («Доставка» → число рядом), она подставляется в заявку и включает чекбокс «Включить доставку» автоматически.

Реестр заявок

Поиск

Поиск работает по: названию заявки, МОЛ, номеру спецификации, номеру Битрикс, наименованиям позиций.

Организация и номер счёта поставщика в текстовый поиск не входят — для них есть отдельные фильтры ниже.

Фильтры

ФильтрОписание
ОрганизацияТолько заявки выбранной организации
МесяцПо дате заявки
СтатусСм. таблицу статусов ниже
ПоставщикПо полю «Поставщик» (сторона в шапке документа)

Пагинация

25 / 50 / 100 заявок на странице. Появляется автоматически когда заявок больше выбранного размера страницы. Детальная разметка строки (позиции, кнопки, статус раскладки файлов) строится лениво — только при первом разворачивании конкретной заявки, а не заранее для всех строк страницы.

Статусы

Экспорт

Кнопка «📊 Экспорт реестра» — .xlsx с текущими фильтрами и итоговой строкой. Кнопка «📄 CSV» рядом — тот же набор данных в CSV (точка с запятой как разделитель, UTF-8 с BOM — открывается в Excel без кракозябр с кириллицей) для внешних систем/BI, которым проще работать с CSV, чем с .xlsx.

Excel экспорт

Генерируется файл {краткое_название_орг}_Расчеты_{номер_спецификации}.xlsx с двумя листами.

Лист 1 — Расчёты

Структура соответствует оригинальному ручному шаблону:

СтрокаСодержимое
1Пустая
2«Потребности пользователей» + «Доставка» + сумма
3Заголовки колонок (ЮЛ, ФИО, №ПП, Наименование, ...)
4+Позиции с расчётными полями, включая долю доставки в числовом и процентном соотношении
n+1Итого
n+3Прибыль

Все денежные формулы (цена закупа, доля доставки, цена с доставкой, цена/сумма продажи, итого, прибыль) обёрнуты в ROUND(...,2) — значения не «плывут» длинными хвостами дробей ни в кэшированном значении, ни при пересчёте формулы в Excel.

Лист 2 — Спецификация

Таблица с ценами продажи. Для типа документа «Реализация» — только позиции ИП, не все строки.

Импорт обратно

Файл, экспортированный отсюда, можно загрузить через «Импорт позиций из Excel» в форме заявки — импорт узнаёт собственный формат по заголовкам колонок и подставляет закупочную (не продажную) цену и сумму доставки автоматически. Подробнее — в разделе «Заявки → Импорт из Excel».

Интеграция Bitrix24

Кнопка 🔗 Bitrix24 в форме заявки отправляет данные через входящий webhook — создаёт сделку в CRM с описанием позиций и суммой. Кнопка скрыта, пока webhook не настроен.

Настройка

  1. В Bitrix24: Настройки → Разработчикам → Входящий webhook
  2. Добавить права: crm
  3. Скопировать URL вида https://your.bitrix24.ru/rest/1/ключ/
  4. Вставить в procure-it: Настройки → Интеграция Bitrix24 → Webhook URL (этот блок специально в самом низу страницы настроек — большинству он не нужен)
Webhook не передаётся в JSON-бэкап и маскируется в GET /api/settings. Пароль сетевой папки тоже не попадает в бэкап.

Спецификация

Предпросмотр спецификации в браузере: кнопка «📄 Спецификация» в форме или «Спецификация» в раскрытой строке реестра.

Печать в PDF: кнопка «Печать / PDF» → в диалоге выбрать «Сохранить как PDF». Кнопка «Сохранить в Word» скачивает .docx, сгенерированный на сервере (POST /api/spec-docx) — красная строка (первая строка абзаца, 1.25см) сделана через явный символ табуляции + табстоп, а не через свойство w:ind firstLine: это надёжнее при печати в реальном Word.

Файл называется {краткое_название_орг}_Спецификация_{номер}.docx — например ЛД_Спецификация_П202608-01.docx.

Содержимое зависит от типа документа заявки (см. «Заявки → Тип документа»): для «Товаров»/«Услуг монтажа» — заголовок, ссылка на договор, дата, таблица позиций, итого, условия поставки, порядок оплаты, блок подписей Поставщик/Покупатель. Для «Реализации» — без ссылки на договор и без порядка оплаты, подпись только одной стороны. Для «Сопровождения» — «Акт гарантийного обслуживания» с гарантийным сроком и условиями покрытия, без порядка оплаты.

О системе

Отдельная страница (доступна админам) — динамическая, не статический текст:

  • Окружение — версия Node.js, платформа, время работы, память процесса, размер БД, время последнего бэкапа; обновляется каждые 10 секунд
  • Технологии — курируемое описание стека (строится по факту наличия пакета в зависимостях, а не захардкожено)
  • Последние изменения — раскрывашка, парсит CHANGELOG.md напрямую (см. «Автотесты и CHANGELOG») — отдельного дублирующего списка в коде нет
  • Зависимости — полный список из package.json с реально установленными версиями (резолвятся из node_modules), плюс кнопка «🔄 Проверить обновления» — по требованию дёргает npm outdated --json и подсвечивает устаревшие пакеты

Компактный мини-виджет с версией, ссылкой на GitHub и лицензией MIT (со скачиванием текста по клику) есть и в сайдбаре — виден всегда, независимо от роли.

HTTPS

При первом запуске автоматически генерируется самоподписанный сертификат RSA-2048 сроком на 10 лет.

data/certs/cert.pem   # сертификат
data/certs/key.pem    # приватный ключ

Чтобы использовать собственный сертификат — замените файлы и перезапустите сервер.

HTTP-порт (PORT+1, по умолчанию 9112) автоматически редиректит на HTTPS.

Бэкап

Автоматический

Запускается через 10 секунд после старта, затем каждые 6 часов. Снапшот БД сохраняется в data/backups/zakupki_YYYY-MM-DD_HH-MM.db (или в настроенную папку — см. ниже), файлы старше 30 дней удаляются автоматически.

Одновременно синхронизируется files_mirror/ — зеркало прикреплённых файлов (подписанные PDF-спецификации, счета). Сами файлы хранятся на диске отдельно от SQLite, поэтому снапшот .db их не содержит — зеркало закрывает этот пробел. Копируются только новые/изменённые файлы, зеркало не версионируется и не растёт бесконечно.

Своя папка для бэкапов

Настройки → Резервная копия → «Папка для автобэкапов» — необязательное поле. Пусто — поведение как раньше (data/backups внутри проекта). Если бэкап лежит там же, где рабочие данные, при поломке того же диска пропадает и он — можно указать путь на другом диске или сетевой ресурс (D:\Backups\zakupki, \\nas\backups\zakupki). Если настроенный путь недоступен на момент бэкапа — сервер откатывается на дефолт и пишет об этом в лог, не роняя бэкап целиком.

Ручной (из интерфейса)

Раздел «Настройки» (внизу страницы) → кнопки:

  • 💾 Скачать JSON — полный экспорт в JSON: организации, заявки, адреса, шаблоны, пользователи и все настройки (включая поставщика по умолчанию)
  • 🗄️ Скачать DB — скачать SQLite файл (заодно синхронизирует зеркало прикреплённых файлов)
  • 📂 Восстановить из JSON — загрузить JSON бэкап
Перед восстановлением показывается модалка с реальными цифрами «сейчас в системе / будет из файла» (заявки/организации/пользователи) и датой формирования бэкапа — вместо голого подтверждения без деталей. При восстановлении сервер сначала ищет прикреплённый файл на месте, а если его там нет (например, диск был потерян) — берёт из files_mirror/ (проверяет и текущую настроенную папку бэкапа, и старую дефолтную, если папка менялась).

POST/PUT отклоняют дубли (409) — по короткому названию и по фактической папке раскладки файлов, регистронезависимо (включая кириллицу). Две организации с одинаковым коротким названием иначе физически раскладывались бы в одну и ту же папку на диске. POST /orgs/bulk не откатывает всю пачку из-за одной проблемной строки — каждая строка обрабатывается независимо (дубль с БД, дубль внутри самого списка или незаполненные обязательные поля отмечаются как skipped/error, остальные добавляются).

Операторам (не admin) в ответе GET /api/settings скрыты инфраструктурные поля: сетевая папка/логин/пароль, webhook'и Bitrix/статусов и SMTP-параметры (smtpHost/smtpUser/smtpPass/smtpFrom).

SMTP (сброс пароля и уведомления). Настраивается в разделе «Настройки» → блок «📧 SMTP». Поддерживаются любые SMTP-серверы (Yandex, Gmail, корпоративный Exchange/Postfix). После заполнения полей кнопка «Тест соединения» отправляет тестовое письмо через POST /api/settings/smtp-test. Когда SMTP настроен, на странице логина появляется ссылка «Забыли пароль?» — пользователь вводит email, получает письмо со ссылкой /reset-password?token=... (токен действует 1 час). Если SMTP не настроен — показывается инструкция «обратитесь к администратору», который может сбросить пароль вручную кнопкой 🔑 в разделе «Учётные записи».

package.json — единственный источник правды. Номер версии больше не редактируется вручную в README/доках — при бампе версии меняется только package.json → version, а затем запускается синхронизация: 
npm run version:sync
Скрипт (scripts/sync-version.js) сам подставит новый номер во все места, где он отображается: бейдж в README, версия в шапке и футере этой страницы, тег Docker-образа в docker-compose.yml. Иллюстративные примеры формата (как в таблице выше) скрипт не трогает — только реальные «текущая версия» плейсхолдеры, помеченные комментариями <!--VERSION-->…<!--/VERSION--> в исходниках.

Автотесты и CHANGELOG

Тесты

Встроенный тест-раннер Node (node --test), без новых зависимостей:

npm test

Покрытие: формула расчёта цены с наценкой и долей доставки (public/js/pricing-core.js — общий модуль, используется и формой заявки, и Excel-экспортом, и сервером при пересчёте итоговых сумм заявки, чтобы не рассинхронизироваться), генерация .docx (табуляция вместо w:ind, невидимые границы служебных таблиц, ширина таблицы, содержимое по типам документа), миграция схемы БД, парсер CHANGELOG.md, аутентификация (соль-на-пользователя, миграция legacy-хэшей, timing-safe сравнение), валидация позиций и восстановление из бэкапа. Подключено в CI (.github/workflows/ci.yml).

E2e-тесты (Playwright)

Отдельный слой поверх unit-тестов — гоняет настоящий Chromium против настоящего сервера (реальные клики, реальная форма логина, а не только HTTP-запросы напрямую):

npx playwright install chromium   # один раз
npm run test:e2e

Сеттап-проект (e2e/auth.setup.js) заводит admin/operator/viewer через API один раз на весь прогон и сохраняет сессию (storageState — токен в localStorage, приложение не использует куки для сессии), остальные тесты подключают готовую сессию вместо повторного прохождения формы логина. Покрытие: логин-форма и гостевой режим, организации (создание, дубликат короткого названия, редактирование, удаление), полный цикл заявки (создание с проверкой формулы наценки прямо в форме → сохранение → поиск в реестре → смена статуса → редактирование с пересчётом суммы → удаление), ролевые границы viewer/operator/admin — включая прямые API-запросы в обход UI (403/400 от сервера, не только «кнопка скрыта»). Сервер поднимается на изолированной временной директории данных (PROCURE_DATA_DIR) — не трогает data/ репозитория. Пока не подключено в CI — прогоняется вручную.

CHANGELOG.md

CHANGELOG.md в формате Keep a Changelog — единственный источник истины по истории изменений. Раздел «Последние изменения» на странице «О системе» парсит именно этот файл, отдельного списка в коде нет.

Pre-commit git-хук (scripts/hooks/pre-commit, ставится автоматически при npm install через prepare) напоминает обновить CHANGELOG.md, если в коммите меняются файлы в src/, public/js/ или public/*.html, а сам changelog не тронут. Не блокирует намертво — просит подтверждения в интерактивном терминале, в CI/GUI-клиентах только предупреждает.
